## Confirmed direct-RPC subscription bypass fixed — 2026-11-17
- Audited live DEV PostgreSQL definitions for seven security-sensitive Academy / CRM RPCs. Six already invoked `public.saas_subscription_access_v1`, but `public.saas_academy_v1(uuid,uuid,text,text,uuid,jsonb)` did not, despite having the Academy module-entitlement check. This permitted an active organization's service-mediated Academy CRUD path to bypass expired-subscription enforcement.
- Added idempotent, structure-checked migration `database/saas/71_phase4d_academy_subscription_rpc_guard.sql` in commit `72105238a80f2ff74455ef726410e7bf76607075`; applied **to DEV only** and verified the definition includes the subscription guard. The service-only RPC grants remain unchanged; `anon` and `authenticated` cannot directly execute the function.
- Re-queried DEV: all **7/7** examined RPC definitions now contain the guard.
- Added source regression assertion to `lib/server/saas/phase4e-subscription-security.test.mjs` (commit `c1b657ce107f1d9ba05810d31c915565aaf1d42d`) and extended authenticated CI trigger (commit `b999d7d99e9de69e3ee7e785f3fe6ef9b7bc3960`).
